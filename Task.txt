Deploy and host the application: Extend your previous secure group-chat application and deploy its backend on at least 3 allotted systems. Host the application through a Load Balancer, so that clients access only the Load Balancer URL/port.
Implement Dynamic Load Balancing: The Load Balancer must dynamically select a backend using response time and/or current system load,rather than simple fixed Round-Robin routing.  It must monitor backend health and stop sending requests to an unavailable backend.
Demonstrate Dynamic Scaling: Start the system with one backend, generate increasing load, and then initialize additional backend systems while the application is running. The Load Balancer should automatically detect the new backend and start distributing traffic to it. Explain and show how the system performance changes after each backend is added.
Ensure Database Persistence and No Duplicates: All backend servers must use persistent storage and share the same chat data. Every message must have a unique message ID, and your database/application must prevent duplicate insertion when the same message is received multiple times, such as during retries or reconnections.
Perform Experiments and Analysis: Generate increasing load from your local system and record response time, throughput, successful/failed requests, and number of active backends. Your report must include at least a Response Time vs Load graph , throughput vs offered load aand a graph showing the effect of adding new backend servers, along with comparison tables and analysis.
Submission and Demonstration: This is an individual assignment. Submit a single PDF report containing student details, assigned systems and ports, architecture, Load Balancer design, database/duplicate-prevention approach, graphs,comparison tables, relevant screenshots, and source-code/GitHub link. Demonstrate dynamic backend addition, persistence, duplicate prevention, and backend failure/recovery on the allotted systems.
